# دليل جمع البيانات الليبية (صور + مستندات)

جودة النموذج تعتمد على البيانات أكثر من اعتمادها على المعمارية. الهدف هو أن يرى النموذج
**نفس نوع الصور التي سيفحصها لاحقاً**: صور ليبية حقيقية مرّت عبر واتساب وفيسبوك وتيليجرام،
وصور مزيّفة صُنعت بأدوات الذكاء الاصطناعي التي يستخدمها الناس فعلاً.

## 1. الفئات (category)

| المجلد | أمثلة |
|---|---|
| `receipt` | إيصالات نقاط البيع (معاملات Moamalat، تداول، سداد، LyPay، ...)، إيصالات الإيداع والتحويل، لقطات شاشة تطبيقات المصارف |
| `id_card` | البطاقة الشخصية، الرقم الوطني، رخصة القيادة |
| `passport` | جوازات السفر والتأشيرات |
| `family_book` | كتيب العائلة، شهادات الميلاد |
| `certificate` | الشهادات الجامعية والمدرسية، كشوف الدرجات، شهادات الخبرة |
| `invoice` | الفواتير، عروض الأسعار، الأختام والتوقيعات |
| `letter` | الرسائل الرسمية، المراسلات الحكومية |
| `photo` | صور أشخاص، أماكن ليبية، أحداث، حيوانات، ... |
| `social` | صور منشورة على فيسبوك/تيليجرام (أخبار، شخصيات عامة) |
| `screenshot` | لقطات شاشة محادثات، منشورات، تحويلات |

## 2. البيانات الحقيقية (`data/raw/real/<category>/<source>/`)

- صوّر المستندات **بأجهزة متعددة** (سامسونج، آيفون، شاومي، هواوي، أجهزة قديمة)، بإضاءات مختلفة، وبالماسح الضوئي أيضاً.
- لكل صورة احفظ عدة نسخ كما تصل في الواقع: الأصلية، المرسلة عبر واتساب، المنشورة على فيسبوك، لقطة شاشة لها.
  (لا مشكلة في التكرار: `build_manifest.py` يجمع النسخ المتشابهة في مجموعة واحدة حتى لا تتسرّب إلى مجموعة الاختبار.)
- اسم المجلد الفرعي `<source>` حر، مثل `moamalat` أو `whatsapp` أو `scanner`.

## 3. البيانات المزيّفة (`data/raw/fake/<category>/<generator>/`)

اسم المجلد `<generator>` هو اسم الأداة: `gemini`, `chatgpt`, `grok`, `meta_ai`, `flux`, `midjourney`,
`qwen_edit`, `photoshop_ai`, `synthetic_copymove`, ...

نوعان من التزييف، وكلاهما ضروري:

1. **توليد كامل**: اطلب من الأداة صورة كاملة ("إيصال معاملات بمبلغ ...", "بطاقة شخصية ليبية", "صورة لاعب في طرابلس").
2. **تعديل جزئي** (الأخطر في الإيصالات): خذ صورة حقيقية وعدّل جزءاً منها فقط (المبلغ، التاريخ، الاسم، الصورة الشخصية).
   **سمِّ الملف المعدّل باسم الأصلي ثم `__`**: إذا كان الأصلي `IMG_0042.jpg` فالمعدّل يكون `IMG_0042__amount.jpg`،
   فيبقيان في نفس المجموعة. هذا يجعل النموذج يتعلّم الفرق الحقيقي بين الصورتين، لا الفرق بين مستندين مختلفين.

بعد ذلك أرسل جزءاً من المزيّف أيضاً عبر واتساب/فيسبوك، كما في البيانات الحقيقية تماماً.

لتكثير أمثلة التعديل الجزئي آلياً من المستندات الحقيقية:

```bash
python scripts/make_tamper_fakes.py --real data/raw/real/receipt --out data/raw/fake/receipt \
    --masks data/masks/receipt --per-image 2
```

## 4. العلامات المائية (مثل نجمة Gemini ✦)

Gemini وMeta AI وغيرهما تضع شعاراً صغيراً في الزاوية. **لا تعتمد عليه**: يمكن قصّه بسهولة، ويمكن لصقه على صورة حقيقية.
- احتفظ بنسخ مزيّفة **مع** الشعار و**بعد قصّه**.
- التدريب يلصق علامات مشابهة عشوائياً على الصور الحقيقية والمزيّفة معاً (`augment.corner_mark`)،
  حتى يتعلّم النموذج آثار التوليد نفسها وليس الشعار.

## 5. الكميات المقترحة

| المرحلة | لكل فئة مستندات | للصور العامة |
|---|---|---|
| نموذج أولي | 500 حقيقي + 500 مزيّف | 5,000 + 5,000 |
| نموذج جيد | 3,000 + 3,000 | 30,000 + 30,000 |
| إنتاج | 10,000+ لكل جهة، و5 أدوات توليد أو أكثر | 100,000+ |

للصور العامة ابدأ بمجموعات بيانات عامة (مثل GenImage وCommunity Forensics وChameleon، وDocTamper للمستندات)
ثم أضف البيانات الليبية فوقها. ابحث عنها في Hugging Face وتحقق من رخصة كل واحدة.

## 6. التحقق من التعميم

احجب أداة كاملة عن التدريب لترى هل يكشف النموذج أداة لم يرها من قبل:

```bash
python scripts/build_manifest.py --root data/raw --out data/manifest.csv --holdout-generators grok
```

## 7. الخصوصية (مهم جداً)

البطاقات والجوازات والإيصالات **بيانات شخصية ومالية**.
- اجمعها بموافقة أصحابها، أو استخدم مستندات تجريبية أو منتهية.
- لا ترفعها إلى GitHub أبداً (`data/` موجود في `.gitignore`)، وخزّنها مشفّرة.
- لا تطمس الأرقام في الصور الحقيقية فقط دون المزيّفة، فالطمس نفسه يصبح علامة يتعلّمها النموذج.
  إن احتجت للطمس فاطمس النسختين بنفس الطريقة.
